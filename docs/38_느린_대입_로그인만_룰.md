# 38. 느린 대입(brute_slow) — "로그인만 하고 서핑은 안 한다" 룰 (2026-11-18)

`docs/37` 에서 느린 BOLA 는 임계값 룰(`uniq_objects ≥ 5`)이 LOF 와 같은 탐지를 오탐 0 으로 했다.
느린 대입도 같은지 본다. 양(요청 수)이 아니라 **행동 구성**을 본다 — 정상 사용자는 로그인한 뒤 상품·주문을 둘러보고, 대입 공격은 로그인만 반복한다.

## 룰

> 같은 출발지, 5분 구간에서 로그인 요청 ≥ N **그리고** 그 구간 요청 중 로그인 비율 ≥ R

데이터: `datasets/real_web/real_canon_access.log.gz` + `real_canon_answer.csv` (출발지 × 5분, 정상 214구간). 재현 `python docs/38_결과/login_only_rule.py` → [`38_결과/output.txt`](38_결과/output.txt)

| 룰 | brute_slow | brute_fast | 정상 오탐 | 다른 공격 |
|---|---|---|---|---|
| 로그인 ≥3 · 비율 100% | 4/5 | 2/5 | 0/214 | 0 |
| 로그인 ≥3 · 비율 ≥90% | 4/5 | 4/5 | 0/214 | 0 |
| **로그인 ≥2 · 비율 ≥80%** | **5/5** | 4/5 | **0/214** | 0 |
| (비교) LOF — 모델 카드 | 5/5 | 4/5 | 처음 보는 정상 출발지 10~15% | |

## 결론

- 느린 대입도 BOLA 와 같은 모양이다. **말로 정의할 수 있는 행동은 룰이 같은 탐지를 오탐 0 으로 한다.**
- ML 의 몫은 말로 정의하지 못한 이상이다. 지금 그 자리에 있는 `harvest_slow`(정상 속도로 한 경로만 긁기)는 이 룰도 LOF 도 0/3 이다.

## 한계

- 정상은 스크립트라 로그인 뒤 반드시 둘러본다. 실제 사람은 비밀번호를 두 번 틀리고 나가기도 한다 → 실제 트래픽에서 오탐을 다시 재야 한다.
- 룰을 아는 공격자는 사이사이 조회를 섞어 비율을 낮출 수 있다. 계정 단위(같은 계정에 여러 출발지)로 보는 룰이 다음 후보다.
