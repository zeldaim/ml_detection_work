# 39. 지름길 피처를 빼고 다른 피처로 탐지하면 되나 (2026-11-18)

질문: 피처 하나가 정답지처럼 정상과 공격을 다 가르면(지름길), 그 피처를 빼고 나머지로 탐지하면 되지 않나?

답: **뺄 수는 있다(피처 소거). 그러나 먼저 "왜 혼자 다 가르는가"를 봐야 한다 — 원인에 따라 처방이 반대다.**

## 경우 1 — 데이터를 만든 방식의 흔적 → 피처가 아니라 데이터를 고친다

`docs/33` 합성 데이터(`data/features_combined.csv`): `err_ratio` AUC **1.000**. 정상 생성기가 오류를 한 번도 내지 않아 정상 37구간이 전부 0이었다. 실제 사람은 오타 · 없는 페이지로 오류를 낸다.

여기서 `err_ratio` 만 빼면:
- 같은 흔적을 다른 피처가 이어받는다. 생성기 정상은 간격도 기계적이라 `interval_cv` 가 다음 지름길 후보.
- 실제로 오류가 많은 공격(대입)을 잡는 진짜 신호까지 버린다.

처방은 정상 데이터를 사람처럼 만드는 것 — `docs/35` 에서 OTTO 재생 정상으로 바꾸자 단일 피처 최대 AUC 0.81(지름길 없음).

## 경우 2 — 공격의 정의 자체 → 빼지 않는다, 룰로 쓸 수 있는지 본다

실제 랩 데이터(`real_canon`)에서 `uniq_objects` 는 BOLA 계열을 혼자 가른다(AUC 1.000). 지름길이 아니라 BOLA 의 정의("남의 객체를 여러 개 건드림")다. 빼면 탐지만 약해진다.
이 피처 하나로 충분하면 결론은 `docs/37` — 임계값 룰(`uniq_objects ≥ 5`)이 LOF 와 같은 탐지를 오탐 0/356 으로. 느린 대입도 같은 모양(`docs/38`, "로그인만" 룰 5/5 · 0/214).

## 같은 피처가 두 경우 모두일 수 있다

| 피처 | 합성 데이터 | 실제 데이터 |
|---|---|---|
| `err_ratio` | 지름길 (정상 쪽이 비현실적으로 전부 0) | brute_slow 의 진짜 신호 (실패 로그인) — AUC 1.000 |
| `uniq_objects` | 0.834 | BOLA 의 정의 — AUC 1.000 |

→ "이 피처를 뺄까"는 **피처 단위가 아니라 데이터 단위**로 판단한다.

## 확인 순서

1. 그 피처가 **다른 출처의 데이터**(실제 로그 · 다른 앱 · 재생 정상)에서도 혼자 가르는가 — `ml/shortcut_auc.py`
2. 안 가른다 → 데이터가 만든 흔적. 정상 데이터를 고친다. 빼더라도 **뺀 뒤 지름길 진단을 다시** 돌려 다음 피처가 자리를 잇지 않는지 본다.
3. 가른다 → 공격의 본질. 남기고, 룰로 쓸 수 있는지 본다(쓸 수 있으면 ML 보다 정확하고 설명 가능).

## 이미 한 것

- 소거 실험: 모델 카드 §3 (예: `rel_*` 소거 시 LOF 0.88 → 0.81)
- 지름길 진단: `docs/33` §2 (합성 있음 · 실데이터 전체 없음 · 종류별 있음)
- 데이터 교체: `docs/35` (OTTO 재생 정상)
